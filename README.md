# TTL2NIM Red Pitaya converter

TTL2NIM converter app for Red Pitaya (Zynq `xc7z010clg400-1`).\
Project created for Vivado 2025.2.

Provides:
- Bazaar app with ability to change signal delays in real time.
- Vivado project to change FPGA design and build it.

## Layout

| Path                                           | Contents                                                                                             |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `src/`                                         | Verilog sources                                                                                      |
| `constraints/`                                 | XDC constraints                                                                                      |
| `app/`                                         | Red Pitaya Bazaar app sources – should be built before use                                           |
| `lib/`                                         | Helper scripts used by other scripts                                                                 |
| `build/` (generated by `recreate_project.tcl`) | Vivado project                                                                                       |
| `out/` (generated)                             | Project outputs, like FPGA bitstream or app build                                                    |
| `design.info`                                  | Facts about the FPGA design (name, delay widths, GPIO address); change only together with the design |

### Scripts

#### `export_project.tcl`

> Stores Vivado project settings and block design, generates `recreate_project.tcl`.

#### `recreate_project.tcl`

> Recreates Vivado project.

#### `redpitaya_genbin.sh [path]`

> Converts Vivado's bitstream output from `.bit` to `.bit.bin` format, which then can be executed on Red Pitaya's FPGA.
> - `[path]`: path to design's bitstream output, extension omitted.\
>   Example: `./build/redpitaya_ttl_to_nim.runs/impl_1/ttl_to_nim_wrapper`
>     - If *provided*, `.bit.bin` is generated at the same path.
>     - If *omitted*, the bitstream is found automatically, generated `.bit.bin` is renamed to module's name and put into `out/`.

#### `build_app.sh`

> Fills templates and builds Red Pitaya Bazaar app sources from `app/` into release bundle in `out/ttl2nim`. The app release then can be installed via `<release>/install.sh` or via prompt in the end of build.

#### `<release>/install.sh [host]`

> Installs the Bazaar app on Red Pitaya. The controller and device tree overlays are built on the board itself (needs `dtc`, usually present on official images), then swapped in for `/opt/redpitaya/www/apps/ttl2nim`, and nginx is restarted. User edits in `settings.conf` are carried between installations.
> - `[host]`: board address, e.g. `rp-xxxxxx.local` (user is `root` unless given as `user@host`).
>     - If *provided*, the release is copied to the board over SSH and installed there.
>     - If *omitted* on a PC, the address is asked for.
>     - If *omitted* on Red Pitaya, the release is installed from where it is.
>
> A failed or interrupted install keeps the previously installed app.
>
> To uninstall the app, simply remove `/opt/redpitaya/www/apps/ttl2nim`.

## Bazaar app

### Build

Requires `jq` and `bootgen` (shipped with Vivado/Vitis) on the build machine, and a generated bitstream (see [Vivado project](#vivado-project)). On the board, Red Pitaya OS 2.x.

```sh
./build_app.sh
```

This stages the release in `out/ttl2nim/` and offers to install it right away.

### Install

To install the app from build artifact or from release:

```sh
<release>/install.sh rp-xxxxxx.local
```

### Usage

Open *TTL2NIM* from Red Pitaya's home screen, or go to `http://rp-xxxxxx.local/ttl2nim/`. Opening the app loads the converter's bitstream to FPGA.

- Coarse delay is set in ticks of the FPGA clock (8 ns), fine delay – in fractions of a tick.
- Arrow buttons change a delay by 1 or 16 steps, $\varnothing$ resets it to 0.
- Delays are persisted on the board and restored the next time the app loads.
- The converter is robust. Reloading the page or opening it on another device doesn't interrupt the output.
- Opening Home screen or another app stops the app and unloads the converter bitstream.

> [!note]
> Persistent state of the app is stored in `/root/.config/redpitaya/apps/ttl2nim/`.

### Configuration

After install, some settings may be configured in `/opt/redpitaya/www/apps/ttl2nim/settings.conf` (the dir into which your app was installed).


| Parameter      | Description                                                                                                                                                        | Value            | Default |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------- | ------- |
| `save_delay_s` | How long to wait after the last change before persisting delays. Each consequent change resets this timer. The writes are then debounced and don't harm SD memory. | integer, seconds | 30      |

> [!tip]
> Don't edit `settings.conf` in release folder, unless it is installed on Red Pitaya with a script. The values there are defaults for reference, and they won't affect your current installation.
>
> Don't edit `design.info` unless changing the FPGA design itself. In context of app, these are read-only instructions of how to communicate with current design. Changing it may lead to undefined behavior and errors.

## Vivado project

To access project's block design and other configurations, install Vivado 2025.2, then run from repo root:

```sh
vivado -mode batch -notrace -source recreate_project.tcl
```

This creates the project in `./build/`. Open `build/redpitaya_ttl_to_nim.xpr` in Vivado.

> [!important]
> - Must be run from the repo root — source paths in the script are relative to it.
> - Requires Vivado version 2025.2. The embedded block design refuses to build on other versions and needs to be fixed manually.
> - Keep new sources in `src/` / `constraints/`. Add them via _Add Sources_ **without** "Copy sources into project", otherwise they get copied into the ignored `build/` and the script won't find them on restore.
> - Don't use incremental synthesis with a reference checkpoint (`utils_1`): the `.dcp` is ignored, so the restore would fail on a missing file.

> [!warning]
> Restoring fails if `build/` already exists. If so, remove old `build/`.
>
> Be aware that internal project sources **will be lost**. Make sure all the sources are stored outside of `build/` before this step.

### Save changes

**Verilog / XDC edits:** nothing to export, just commit `src/` and `constraints/`.

**Block design, project settings, added/removed files:** re-export the script, then commit it. To export changes, in the Vivado Tcl console:

```tcl
source -notrace [get_property DIRECTORY [current_project]]/../export_project.tcl
```

> [!caution]
> In case `recreate_project.tcl` was updated elsewhere (e.g. after a pull), restore the project from it before making changes. Otherwise your next export would **overwrite those updates** with your older project.

> [!tip]
> If no changes were made in project itself, `rebuild_project.tcl` will show only changed export timestamp, which is commented. Sometimes builds may result in GUI block positions noise.

### Launching on Red Pitaya

1. In Vivado, run implementation, then generate bitstream.
2. Convert the `.bit` implementation file to the `.bit.bin` bitstream format with `./redpitaya_genbin.sh`.
   - Ensure that `bootgen` is in the PATH. It's shipped with Vivado/Vitis.
3. Copy the bitstream file to Red Pitaya. For example:
    ```sh
    scp ./out/ttl2nim.bit.bin root@rp-xxxxxx.local:/tmp/ttl2nim.bit.bin
    ```
4. On Red Pitaya, run:
    ```sh
    fpgautil -b /tmp/ttl2nim.bit.bin
    ```
